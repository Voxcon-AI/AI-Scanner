# Story 1.1: Project Initialization and Monorepo Setup

## Status

Ready

## Story

**As a** developer,
**I want** a properly initialized Node.js monorepo with shared workspace configuration,
**so that** all services can share common utilities and dependencies efficiently.

## Acceptance Criteria

1. Git repository initialized with .gitignore excluding node_modules, .env, and common Node.js artifacts
2. Root package.json configured with workspaces for services/ subdirectories (watcher, worker, api, mailer)
3. Node.js v24.5.0 specified in package.json engines field and .nvmrc file
4. Shared workspace created at shared/ directory with common utilities (logger config, constants, types)
5. ESLint and Prettier configured for consistent code formatting across all services
6. README.md includes project overview and links to setup documentation
7. LICENSE file added (MIT or Apache 2.0 for open source)
8. .env.example file created with placeholder values for all required environment variables

## Dev Notes

### Project Structure Context

[Source: architecture/unified-project-structure.md]

The monorepo follows this structure:

- Root directory contains package.json with workspaces configuration
- services/ subdirectory will contain: watcher, worker, api, mailer (created in future stories)
- shared/ workspace at root level for shared TypeScript types and utilities
- Frontend lives in frontend/ directory (static assets, no workspace package)
- Docker Compose configs in docker/ directory
- Documentation in docs/ directory

### Technology Stack

[Source: architecture/tech-stack.md]

- **Node.js Version:** v24.5.0 (specified in package.json engines field and .nvmrc)
- **Build Tool:** esbuild via tsx for TypeScript transpilation (100x faster than tsc)
- **Backend Language:** TypeScript 5.3+ transpiled to JavaScript
- **Bundler:** None for backend (uses Node.js native ESM), esbuild for frontend
- **No ORM:** Using raw SQL with pg library instead of TypeORM/Prisma
- **Workspace Management:** npm workspaces (native to npm 7+)

### Shared Package Structure

[Source: architecture/unified-project-structure.md#L74-79]

The shared/ workspace must export:

- **Types:** TypeScript interfaces (Document, User, ProcessingQueue, Batch, AnalysisResult)
- **Constants:** Enums, error codes, configuration constants
- **Utils:** Shared functions like filename sanitization, path validation

Services import from shared using: `import { Document } from '@ai-scanner/shared'`

### Critical Coding Standards

[Source: architecture/coding-standards.md#L1-22]

- **Type Sharing:** Always define types in shared/src/types/ and import from @ai-scanner/shared. Never duplicate type definitions.
- **Environment Variables:** Access only through config objects, never use process.env directly in business logic. Validate all required env vars on service startup (fail fast if missing).
- **File Names:** Match primary export name (Button.js exports Button class)
- **Async Functions:** Prefix with async keyword, return Promises
- **Constants:** Use SCREAMING_SNAKE_CASE for environment variables and constants

### Git Configuration

[Source: architecture/unified-project-structure.md#L105]

.gitignore must exclude:

- node_modules/ (dependency cache)
- .env, .env.local (sensitive environment variables)
- dist/ (build output)
- coverage/ (test coverage reports)
- .DS_Store (macOS metadata)
- \*.log (log files)

### Environment Variables Required

[Source: architecture/tech-stack.md, architecture/backend-architecture.md]

The .env.example must document these variables:

- **DATABASE_URL:** PostgreSQL connection string
- **REDIS_URL:** Redis connection string
- **GEMINI_API_KEY:** Google Gemini API key for AI analysis
- **SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS:** Email service configuration
- **JWT_PRIVATE_KEY, JWT_PUBLIC_KEY:** RS256 key pair for JWT signing (PEM format)
- **SCAN_FOLDER_PATH:** Absolute path to network share for scanned files
- **OUTPUT_FOLDERS_BASE:** Base path for destination folders
- **WEB_UI_BASE_URL:** Frontend URL for email links

### Linting and Formatting Configuration

[Source: architecture/coding-standards.md]

- ESLint with TypeScript parser (@typescript-eslint/parser)
- Prettier with: semi: true, singleQuote: true, trailingComma: 'es5', tabWidth: 2
- npm scripts for: "lint" (runs eslint), "format" (runs prettier --write)

### TypeScript Configuration

[Source: architecture/tech-stack.md#L21]

- TypeScript 5.3+ for type-safe Node.js services
- Shares types with frontend via shared package
- Transpiled to JavaScript at runtime via tsx (development) or esbuild (production)
- Root tsconfig.json with strict mode enabled
- Shared package tsconfig.json extends root, outputs to dist/ with declaration files

### Testing

[Source: architecture/testing-strategy.md]

Testing framework: Vitest 1.0+

- Unit tests for utilities and business logic
- Integration tests for API endpoints with Supertest
- Test file naming: {source}.test.ts (e.g., filename.test.ts)

Note: Testing setup is not part of this story's scope (deferred to Epic 6)
